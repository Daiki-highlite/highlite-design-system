# Brandri 記事レビュー運用ルール

Slackチャンネル `#brandri-articles`（`C0BNHP6HU04`）での記事レビューの進め方。

---

## 週次の流れ

```
水曜      Botが記事ドラフトを1本投稿
   ↓
    〜8日間   レビュー期間
   ↓
翌週木曜   承認されていれば公開
```

毎週水曜に1本投稿され、翌週木曜に1本公開される。これが定常サイクル。

---

## リアクションの意味

| 絵文字 | 押す人 | 意味 |
|---|---|---|
| 👀 | 人 | レビュー中・修正待ち |
| 👍 | 人 | 承認 |
| 🗑️ | 人 | ボツ |
| 🗓️ | Bot | 公開日確定（人は押さない） |
| ✅ | Bot | 公開済み（人は押さない） |
| ☑️ | Bot | スレッドコメントの処理済み（人は押さない） |

**👍は「その時点の記事」に対する承認。**
修正が入っても、押した👍が自動で外れることはない。外すかどうかは常に人が判断する。

---

## レビューの進め方

### 1. レビューを始めるとき

親投稿に **👀** を押す。「見ている・レビュー中」の合図。

### 2. 修正してほしいとき

- 親投稿は 👀 のまま
- **スレッドに**コメントを残す（親投稿へのリプライではなく、そのスレッド内）
- Botがコメントを読み取り、記事を修正してスレッドに新しいバージョンを返信する
- 処理済みのコメントには Bot が ☑️ を付ける

コメントは具体的に書く。「もう少し良くして」より「③の実務パートを、久留米の案件じゃなくてリアリスの案件に差し替えて」のように、何をどう直すかが分かる形が望ましい。曖昧なコメントの場合、Botは修正せずに確認の質問を返すことがある。

### 3. 軽微な修正だけしてほしいとき（承認はそのまま）

先に **👍** を押してから、スレッドに軽微な修正コメントを残してよい。
（例：「内容はこれでOK。誤字だけ直して」）

- Botは修正を反映するが、**👍には触れない**
- ただしこの場合、Botはスレッドに以下のような通知を返す：
  ```
  修正を反映しました（v2）
  👍がついた状態での修正です。内容を確認し、
  承認を取り消す場合は👍を外してください
  ```
- 通知を見て、修正内容に問題がなければ何もしなくていい（👍はそのまま有効）
- 修正内容に納得できなければ **👍を外す**

### 4. 承認するとき

内容に問題がなければ親投稿に **👍** を押す。これで公開キューに入る。

### 5. 承認を取り消したいとき

**👍を外す。** これだけでよい。

- 公開日より前に外せば、公開はキャンセルされる
- Botが自動で検知してキャンセル処理を行う（🗓️ を外し、キャンセルした旨をスレッドにコメント）
- 取り消した後、続けてレビューしたい場合は 👀 を押し直す

### 6. ボツにするとき

親投稿に **🗑️** を押す。以降このスレッドは処理対象から外れる。

## リアクションが複数付いたときの判定ルール

Botは毎回、次の順で上から見て、**最初に当てはまった1つ**で状態を決めます
（👍のカウントからBot自身の👍は除外）。

```
1. 🗑️ あり            → ボツ（手動）
2. ✅ あり             → 公開済み
3. 投稿から28日超       → 鮮度切れ
4. 公開予定日を過ぎた    → 自動ボツ（missed）※予定日当日はまだ生存
5. 未処理コメントあり    → 修正待ち
6. 👍 + 🗓️           → 予約済み
7. 👍 あり            → 承認
8. 👀 あり            → レビュー中
9. リアクション無し      → 未着手
```

**公開予定日を過ぎた記事は自動でボツ（missed）になります。**
レビューが8日間のレビュー期間に間に合わず、公開予定日（木曜）当日までに
承認（👍→予約）が完了しなかった記事は、翌日以降のsync/publishで自動ボツになります。
- 予定日**当日**はまだ生きています（その日のpublishで公開可能）
- 落ちた記事は消えず `dropped/` に残り、`_dropped-log.md` に理由付きで記録されます
- Slackの投稿にも 🗑️ が付き、スレッドに「予定日を過ぎたため見送り」と残ります
- トレンドの鮮度を守るための仕様です。出したい場合は、レビューを予定日までに終えてください

このため：

- **👀 と 👍 が両方付いていても、👍 が勝つ（＝承認扱い）。**
  「レビュー中だが承認済み」という中間状態は作らない。
- **👍 が付いた状態でスレッドにコメントすると、修正待ちが優先される**（ルール4 > ルール6）。
  本文を直して `resolve` すると 👍 はそのまま残るので、また承認に戻る。
- **判定に使う絵文字は 👀 / 👍 / 🗑️ / 🗓️ / ✅ / ☑️ の6つだけ。**
  それ以外（🙌 :ok_hand: など）を押しても無視される（害はないが意味も無い）。
  承認は必ず 👍 で。

## よくあるやり取りの例

**通常の1往復で終わるケース**
```
水  Botが記事を投稿
月  Totoが👀 → スレッドに「②の切り口を変えてほしい」とコメント
月  Botがv2を返信、コメントに☑️
火  Totoが読んで👍
翌週木  公開
```

**承認後に気が変わったケース**
```
月  👍
水  読み返して「やっぱりここが引っかかる」→ 👍を外す
水  👀 → スレッドにコメント
木  Botがv2を返信
金  読んで👍
翌週木  公開
```

**承認しつつ軽微修正だけ頼むケース**
```
月  👍 → スレッドに「これでOK。誤字だけ直して」
月  Botがv2を返信＋「👍ついたままです。確認して問題なければそのままで」
月  内容確認、問題なし → 何もしない（👍は有効なまま）
翌週木  公開
```

---

## 注意点

- Botは 👀 / 👍 / 🗑️ を一切操作しない。これらは常に人が管理する
- 🗓️ / ✅ / ☑️ が手動で付いていると、Botの状態判定が狂う可能性がある。これらは触らない
- 修正依頼は必ず**スレッド内**に書く。チャンネルの別投稿やDMでは処理されない
- 公開直前（木曜の処理実行時）に、Botは必ずもう一度👍の有無を確認してから公開する。ぎりぎりの取り消しも反映される
